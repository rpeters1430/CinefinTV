# CinefinTV UI Anti-Slop Audit

- **Audit ID**: audit-001
- **Date**: 2026-09-23
- **Scope**: CinefinTV Android TV User Interface (`app/src/main/java/com/rpeters/cinefintv/ui`)
- **Mode**: Mode 2 (After Project Completion Audit)

---

## Findings List

### 1. Empty Collection Screen Traps D-pad Focus Without Recovery Action
- **Rule**: R-27 — UI States
- **Priority**: HIGH (Hard Gate)
- **Location**: `app/src/main/java/com/rpeters/cinefintv/ui/screens/detail/CollectionDetailScreen.kt:340-353`
- **Reason**: Displays static text ("No items found in this collection") with no interactive recovery button (e.g., "Browse Libraries" or "Back") and no focus target for TV D-pad.

### 2. Empty Playlist Screen Traps D-pad Focus Without Recovery Action
- **Rule**: R-27 — UI States
- **Priority**: HIGH (Hard Gate)
- **Location**: `app/src/main/java/com/rpeters/cinefintv/ui/screens/detail/PlaylistDetailScreen.kt:190-202`
- **Reason**: Displays static text ("No items in this playlist yet") without actionable guidance or a focusable recovery element for TV D-pad navigation.

### 3. Non-Actionable Empty States in Music Views
- **Rule**: R-27 — UI States
- **Priority**: HIGH (Hard Gate)
- **Location**: `app/src/main/java/com/rpeters/cinefintv/ui/screens/music/MusicScreen.kt:220-227, 379-387`
- **Reason**: Empty music views display non-actionable placeholder text ("No albums found.", "No tracks found.") with no recovery CTA or D-pad focus handling.

### 4. Library Empty State Lacks Interactive Recovery Button
- **Rule**: R-27 — UI States
- **Priority**: HIGH (Hard Gate)
- **Location**: `app/src/main/java/com/rpeters/cinefintv/ui/screens/library/LibraryScreenShared.kt:181-217`
- **Reason**: `LibraryGridUiState.Empty` renders an empty surface with "Check your library or server connection" but provides no interactive recovery action (e.g. "Refresh" or "Switch Library"), leaving the TV screen without an active focus anchor.

### 5. Non-Interactive Hero Discovery Tiles Confuse 10-Foot D-Pad Model
- **Rule**: R-26 — Interactive Elements / R-32 — Keyboard Accessibility (D-pad)
- **Priority**: HIGH (Hard Gate)
- **Location**: `app/src/main/java/com/rpeters/cinefintv/ui/screens/home/HomeScreen.kt:911-965`
- **Reason**: `HomeDiscoveryStrip` displays card-styled category pills ("X ready") that look like interactive jump tiles but have no D-pad focus handling, click actions, or jump-to-section navigation.

### 6. Missing Central DESIGN.md Specification
- **Rule**: R-37 — Design Direction Required
- **Priority**: HIGH (Hard Gate)
- **Location**: `DESIGN.md` (root)
- **Reason**: Repository lacks a central `DESIGN.md` specifying brand identity, typographic character, and antislop liveliness dials (ENERGY / RHYTHM / MOTION).

### 7. Redundant "Featured" Eyebrow Badge Above Hero Headline
- **Rule**: R-09 — Badges
- **Priority**: MEDIUM (Purpose-Gate)
- **Location**: `app/src/main/java/com/rpeters/cinefintv/ui/screens/home/HomeScreen.kt:761`
- **Reason**: Decorative "Featured" capsule badge is placed directly above the hero title (H1) as a redundant eyebrow badge duplicating the hero carousel context.

### 8. Redundant Item Type Badge in Library Metadata Header
- **Rule**: R-09 — Badges
- **Priority**: MEDIUM (Purpose-Gate)
- **Location**: `app/src/main/java/com/rpeters/cinefintv/ui/screens/library/LibraryScreenShared.kt:349`
- **Reason**: Redundant item type badge (e.g. "Movie" or "Series") is placed above the title in `LibraryMetadataHeader` even when already viewing dedicated movie or show libraries.

### 9. Sub-16sp Text Size in TV Metadata Chips and Badges
- **Rule**: R-06 — Typography / TV 10-Foot Readability
- **Priority**: LOW (Quality Locks)
- **Location**: `app/src/main/java/com/rpeters/cinefintv/ui/screens/detail/cinematic/CinematicHero.kt:250` and `app/src/main/java/com/rpeters/cinefintv/ui/components/CinefinChip.kt:99`
- **Reason**: Sub-16sp font sizes (13sp in rating tags, 15sp in chips) fall below the 18sp TV baseline and are difficult to read from a 10-foot viewing distance.
